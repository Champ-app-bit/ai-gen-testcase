# v1 — สั่งครั้งเดียว แล้วปล่อยทิ้งไว้

ระบบนี้ **หาบั๊กในโค้ดที่คุณเขียน แล้วแถมเทสอัตโนมัติไว้ให้ด้วย**
ของชิ้นแรกที่ควรเปิดอ่านคือ `findings.md` ไม่ใช่จำนวนเทสเคส

## ขอบเขตความเสียหาย (อ่านก่อน)

| ระบบนี้ | จริงหรือไม่ |
|---|---|
| แตะโค้ด product ของคุณ | **ไม่** เขียนได้เฉพาะ repo automation + โฟลเดอร์เอกสารเทส |
| `git commit` / `push` เอง | **ไม่** ทุก diff รอคุณดูเอง |
| ยิงเทสใส่ env จริงเอง | **ไม่** จนกว่าจะตั้ง `run:` ใน config |
| ยืนยัน spec เองว่าพฤติกรรมไหนถูก | **ไม่** ข้อที่ไม่ชัดเข้าคิวคำถามรอคุณตอบเสมอ |
| หยุดรอคำตอบของคุณ | **ไม่** จดคำถามไว้แล้วทำต่อ ภายใต้สมมติฐานที่เขียนกำกับไว้ |

## ติดตั้ง (ครั้งเดียว)

```bash
git clone <repo เครื่องมือ> && cd ai-gen-testcase
cp commands/*.md ~/.claude/commands/
pip3 install --user pyyaml
```

## ใช้งาน

```bash
./testgen ~/Web/loveryoyflower --domain "ร้านดอกไม้ออนไลน์" --daemon
```

จบ. ปิด terminal ได้ ปล่อยไว้กี่วันก็ได้ มันจะเดินเองทั้ง 6 เฟส:

| เฟส | ทำอะไร | ใช้โควตา |
|---|---|---|
| 1 bootstrap | ตรวจ stack เอง เขียน config ทั้งสองไฟล์ | ไม่ |
| 2 scout | สแกนหา module + จัดอันดับความเสี่ยง (เดา layout ไม่ออกก็เติมเองถ้ามีทางเดียว) | ไม่ |
| 3 นำร่อง | ทำ module แรกแล้ว **ตรวจด้วย verify ก่อน** — ไม่ผ่านจะลองตัวอื่น สูงสุด 3 ตัว | ใช้ |
| 4 batch | ไล่ทุก module ที่เหลือ ตัวไหนติดซ้ำ 2 รอบก็ข้ามพร้อมจดเหตุผล | ใช้ |
| 5 รันจริง | รัน robot กับ env จริง (ข้ามถ้ายังไม่ตั้ง `run:`) | ไม่ |
| 6 รายงาน | รวบผลทั้งเว็บเป็นรายงานที่วิเคราะห์แล้ว | ไม่ |

**เฟส 3 มีอยู่เพราะอะไร**: BASE_URL / flow login / convention ที่ผิด จะถูก clone ไปทุก module
ระบบจึงบังคับให้ module แรกผ่าน `verify` ก่อน ถึงจะปล่อยรันยาว ถ้าไม่ผ่าน 3 ตัวติดมันจะหยุด
แล้วบอกให้คุณทำตัวแรกพร้อมคนหนึ่งรอบ — **ยอมเสียเวลาตรงนี้ ดีกว่าได้เทสผิดแบบเดียวกัน 58 ชุด**

## ดูว่ามันไปถึงไหน

```bash
./testgen loveryoyflower --status     # เฟสไหน module ไหน หัวใจเต้นล่าสุดเมื่อไร คำถามค้างกี่ข้อ
tail -f logs/loveryoyflower-*.log     # ดูสด ๆ
./testgen loveryoyflower --stop       # หยุดสุภาพ: จบ module ที่ค้างก่อน แล้วออกรายงาน
```

โควตาหมดจะขึ้นใน log ว่า `นอนรอ N นาที ตื่น HH:MM` — ไม่ต้องทำอะไร มันสั่งใหม่ที่ module เดิมเอง
ไฟดับ / รีบูต / เผลอปิด: สั่ง `./testgen loveryoyflower` ซ้ำ **ไปต่อจากจุดเดิม ไม่ทำซ้ำของที่เสร็จแล้ว**
(สถานะทุกอย่างอยู่ใน `modules.yaml` ไม่ใช่ในบทสนทนา)

## เปิดคอมทิ้งไว้ข้ามวัน (WSL)

Windows ที่หลับ = WSL หยุดด้วย ตัว autopilot จะค้างกลางทางเงียบ ๆ ตั้งก่อนปล่อยรัน:

```powershell
powercfg /change standby-timeout-ac 0        # ไม่ให้ sleep เมื่อเสียบไฟ
powercfg /change hibernate-timeout-ac 0
```
`--daemon` ใช้ `setsid` แล้ว จึงรอดจากการปิด terminal แต่ไม่รอดจากการปิดเครื่อง

## ตอนจบ: อ่านรายงานอย่างไร

รายงานไม่นับ "เทสแดงกี่เคส" แต่ยุบเป็น **สาเหตุราก** แล้วแปะเจ้าภาพ
(ของจริงที่วัดได้: เทสแดง 45 เคสของ ERP ยุบเหลือ 26 สาเหตุ และสาเหตุเดียวกินไป 14 เคส)

| ป้าย | หมายถึง | ใครรับไปทำ |
|---|---|---|
| ต้องสงสัยเป็นบั๊ก | assert ไม่ตรงคาด (และของที่จัดประเภทไม่ได้ตกมาที่นี่) | **dev — อ่านก่อน** |
| ENV/SESSION | session หลุด / login พัง — เทสยังไม่ได้พิสูจน์อะไร | เจ้าของ environment |
| LOCATOR เก่า | หน้าจอเปลี่ยน ตัวชี้ element ไม่ตรงแล้ว | คนดูแลเทส |
| สคริปต์เทสผิด | เทสเขียนผิดเอง ไม่เกี่ยวกับ product | คนดูแลเทส |

`⚠ ผลเก่า N วัน` = สถานะของวันที่รัน **ไม่ใช่วันนี้** ต้อง `--run-only` ใหม่ก่อนเชื่อ

## ปิดงาน: เคลียร์คำถามทีเดียว

```
claude
/testgen loveryoyflower --answer
```
ถามรวบทีละไม่เกิน 4 ข้อจนหมดคิว ตอบแล้วระบบจัดการต่อเอง — `promote` spec ที่ครบ,
**ตีเทสเคสที่สร้างจากสมมติฐานผิดกลับไปทำใหม่**, ลงบั๊กที่ยืนยันใหม่ใน `findings.md`

## ข้อจำกัดที่ต้องรู้ ไม่ใช่บั๊ก

- **โค้ดบอกได้แค่ว่าระบบทำอะไร ไม่ได้บอกว่าควรทำอะไร** — spec ที่ระบบร่างจึงเป็น `draft`
  จนคุณตอบคำถามแล้ว promote เอง ถ้าปล่อยให้มันยืนยันเอง บั๊กวันนี้จะกลายเป็น requirement
- **เทสที่ยังไม่เคยรันกับ env จริง = ยังไม่พิสูจน์อะไร** รายงานจะบอกตรง ๆ ว่า suite ไหนยังไม่เคยรัน
- **UI เปลี่ยนแล้วเทสพัง** เป็นเรื่องปกติ ต้องมีคนดู รายงานแยกกลุ่มนี้ไว้ให้แล้ว
- **หาบั๊กแบบ "เอ๊ะ มันแปลก ๆ" ไม่ได้** อันนั้นยังต้องเป็นคนกด
- ไม่มีเครื่องมือไหนรับประกันว่าไม่มีบั๊กหลุด รวมถึงตัวนี้

## ติดปัญหา

1. `logs/<project>-<เวลา>.log` — บรรทัดท้าย ๆ บอกว่าตายที่ไหน
2. สถานะงานอยู่ใน `<batch.dir>/modules.yaml` แก้มือได้ (สั่งใหม่แล้วไปต่อจากตรงนั้น)
3. `./testgen <project>` ซ้ำได้เสมอ · `--dry-run` ดูแผนก่อนโดยไม่เรียก claude และไม่แก้ทะเบียน
